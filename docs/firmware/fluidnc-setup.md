## Что такое FluidNC

FluidNC — прошивка для ESP32, GRBL-совместимый CNC-контроллер. Все
пользователи используют одну и ту же прошивку — конкретная машина
описывается конфигурационным файлом `config.yaml`, который заливается на
плату отдельно и читается при старте (если файла нет, поднимается
минимальный дефолтный конфиг только для серийной связи).

В этом проекте FluidNC используется нецелевым образом — не для станка, а как
контроллер движения джиба. Секции `axes`/`motors`/`homing` нужно будет
переосмыслить под механику джиба (см.
[`../hardware/mechanics.md`](../hardware/mechanics.md)), а не под фрезер.

## Формат config.yaml

- Урезанное подмножество YAML: отступы **только пробелами** (рекомендуется 2
  пробела на уровень, табы запрещены), пробел после `:` у ключа, без пробела
  перед значением, комментарии — `#` на отдельной строке.
- Имя файла — до 30 символов, включая `.yaml`.
- Пины именуются с суффиксом `_pin` (`direction_pin`), величины с единицами —
  суффиксом единицы (`spinup_ms`, `steps_per_mm`).
- Верхнеуровневые секции: `stepping`, `axes`, `control`, `coolant`, `probe`,
  `spindles` и др. Можно хранить несколько конфигов на плате и переключаться
  командой `$Config/Filename=<file>.yaml`.

## Секция `axes`

До 6 осей (X, Y, Z, A, B, C), до 2 моторов на ось (`motor0`, `motor1`).
Параметры на ось:

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `steps_per_mm` | float | 80.0 | шагов контроллера на единицу gcode (не обязательно мм — для поворотных осей это "шагов на градус") |
| `max_rate_mm_per_min` | float | 1000.0 | макс. скорость |
| `acceleration_mm_per_sec2` | float | 25.0 | ускорение |
| `max_travel_mm` | float | 1000.0 | рабочий ход от концевика |
| `soft_limits` | bool | false | программные ограничения хода (требуют хоминга) |

Пример мотора на шаговом драйвере TMC2130 (SPI):

```yaml
motor0:
  tmc_2130:
    cs_pin: gpio.17
    spi_index: -1
    r_sense_ohms: 0.110
    run_amps: 0.750
    microsteps: 32
    run_mode: StealthChop
    step_pin: gpio.12
    direction_pin: gpio.26
```

Поддерживаемые типы моторов/драйверов: `standard_stepper` (обычный step/dir),
`stepstick` (+ пины микрошага), `tmc_2130`/`tmc_5160` (SPI, ток/микрошаг/
StealthChop-CoolStep-Stallguard настраиваются программно), `tmc_2208`
(UART, драйверы не адресуемые — на общей шине все получают настройки
последнего сконфигурированного), `tmc_2209` (UART, аппаратно адресуемые,
до 4 шт. на шину через `uart_num`+`addr`), `rc_servo` (ШИМ, `pwm_hz`,
`min_pulse_us`/`max_pulse_us` — диапазон импульса маппится на ход оси),
`solenoid` (вкл/выкл через ШИМ, `pull_percent`/`hold_percent`/`pull_ms`),
Dynamixel Protocol 2 (сервоприводы по UART с ID).

**Важно для нашей конструкции:** raw RC-серво не годится для точного
слежения за быстро меняющимся профилем скорости (задержка отклика может
вызывать рассинхронизацию) — если ось управляется джойстиком в реальном
времени, вероятно нужны шаговые/TMC-драйверы, а не `rc_servo`.

## Секция `stepping`

```yaml
stepping:
  engine: I2S_STATIC        # RMT, TIMED, I2S_STATIC, I2S_STREAM
  idle_ms: 250               # задержка отключения моторов (255 = всегда включены)
  pulse_us: 4                 # длительность импульса шага
  dir_delay_us: 4              # выдержка перед импульсом после смены направления
  disable_delay_us: 0
  segments: 12
```

Макс. частота шагов ограничена как `1 000 000 / (2 × pulse_us + dir_delay_us)`
Гц — реалистично 100–125 кГц.

**Снизу скорость тоже ограничена, и жёстче, чем кажется.** Планировщик
клампит любую подачу ниже 1 ед/мин, а генератор шагов не умеет разносить
шаги дальше ≈26 мс друг от друга — эффективный минимум оси равен
`max(1.0, 2290 / steps_per_mm)` ед/мин, и нарушается он молча (машина едет
быстрее заказанного, `ok` приходит как обычно). Для джиба с его медленными
проездами это определяющее ограничение при выборе микрошага и редукции —
разбор и формулы в
[`fluidnc-slow-motion-limits.md`](fluidnc-slow-motion-limits.md).

## Секция `homing`

```yaml
homing:
  cycle: 2                    # номер цикла хоминга (0 отключает для оси)
  allow_single_axis: true     # разрешить хоминг одной оси ($HX)
  positive_direction: false
  mpos_mm: 1.000
  seek_mm_per_min: 200         # скорость первого касания концевика
  feed_mm_per_min: 50          # скорость точного позиционирования
  seek_scaler: 1.1
  feed_scaler: 1.1
```

Плюс на моторе: `limit_neg_pin`/`limit_pos_pin`, `hard_limits: true`
(аварийная остановка при срабатывании концевика), `pulloff_mm` (отход от
концевика после касания).

## Плата и прошивка

Не выбрана. Требования: ESP32 с достаточным числом GPIO под все оси
устройства, сборка прошивки с включённым Bluetooth (см. ниже).

**Важное ограничение железа ESP32:** одновременно доступен только один
радиомодуль — **WiFi и Bluetooth не работают одновременно**. Есть две
готовые прошивки (WiFi-сборка и Bluetooth-сборка), нужно установить именно
Bluetooth-вариант (либо собрать вручную с `noradio`/комбинированным
вариантом через `platformio.ini`, если такое возможно). Значит: сначала
нужно определиться, что проекту нужно — Bluetooth-управление или WiFi — по
условиям задачи это Bluetooth, WiFi-сборку заливать не нужно.

## Связь с приложением

Управление — по Bluetooth, виртуальный COM-порт, см.
[`../protocol/bluetooth-gcode-control.md`](../protocol/bluetooth-gcode-control.md).
Все радио-настройки (WiFi/Bluetooth) задаются не в `config.yaml`, а через
`$`-команды после прошивки (сделано для стабильности радио независимо от
конфига станка). Ключевая настройка — `$Bluetooth/Name` (имя устройства при
поиске по Bluetooth); список Bluetooth-настроек виден только на
Bluetooth-сборке прошивки (на WiFi-сборке их нет и наоборот).

## Открытые вопросы

- [ ] Выбор конкретной платы (ESP32 dev board с достаточным числом GPIO).
- [ ] Драйверы шаговых двигателей под каждую ось — не выбраны (TMC2209 по
      UART выглядит разумным дефолтом: тихий, до 4 осей на одну шину;
      UART-режим к тому же даёт 256 микрошагов, а высокий микрошаг — это
      способ опустить нижний порог скорости, см.
      [`fluidnc-slow-motion-limits.md`](fluidnc-slow-motion-limits.md)).
- [ ] Итоговый `config.yaml` — нет ни одной версии.
- [ ] Подтвердить наличие/версию Bluetooth-сборки FluidNC для выбранной
      платы и собрать/прошить именно её (не WiFi-вариант).
- [ ] Хоминг: нужны ли концевики на все оси или используется другой подход?
- [ ] Установить `$Bluetooth/Name` на что-то узнаваемое для сопряжения из
      приложения.
