# Шапка MainView: мобильный UX — дизайн

Дата: 2026-08-04

**Опирается на:** `docs/superpowers/specs/2026-08-04-three-band-main-layout-design.md`, который уже привёл шапку к структуре `Border(HeaderBorder) → WrapPanel(HeaderPanel) → [ContentControl(ConnectionStatus), WrapPanel(PlaybackButtons)]` и сделал `HeaderBorder.Bounds.Height` источником для расчёта радиуса джойстиков. Тот дизайн явно оставил вне скоупа визуальный редизайн шапки и изменения `ConnectionView.axaml` — этот документ берёт именно то, что там не сделано.

## Проблема

Шапка сейчас — один `WrapPanel` с 8 элементами вперемешку, без группировки по смыслу:
индикатор связи → машинное состояние/позиция → ошибка (`ConnectionView.axaml`, зона статуса) и следом Homing/Сброс аварии/Отключить (тоже `ConnectionView.axaml`, но это уже действия) → Пуск/Пауза/Стоп → бейдж состояния воспроизведения → Лог G-code (`PlaybackButtons` в `MainView.axaml`). Визуально это выглядит хаотично: кнопки разного веса (primary/danger/обычные) стоят вперемешку, нет единого выравнивания.

На узких экранах телефона `WrapPanel` переносит часть контента на 2-ю или 3-ю строку непредсказуемо (зависит от того, где именно не хватило места), из-за чего высота шапки скачет от кадра к кадру — а она напрямую входит в `ComputeJoystickRadius`, так что радиус джойстиков дёргается вместе с ней.

## Решение: 2 фиксированные зоны вместо одного WrapPanel

**Зона 1 — статус (верхняя строка, не переносится, не скроллится).**
Компактный ряд: индикатор связи + метка состояния соединения, машинное состояние/позиция, бейдж состояния воспроизведения (`PlaybackStateLabel`). Элементов мало (короткие текстовые метки), они помещаются в одну строку на любой ширине от ~360px. Баннер ошибки (`HasError`/`ErrorMessage`), если активен, — отдельной строкой прямо под этой зоной, тоже без переноса кнопок.

**Зона 2 — действия (нижняя строка, горизонтальная swipe-палитра).**
Все командные кнопки — `Homing`, `Сброс аварии`, `Отключить`, `Пуск`, `Пауза`, `Стоп`, `Лог G-code` — в один ряд внутри `ScrollViewer HorizontalScrollBarVisibility="Auto" VerticalScrollBarVisibility="Disabled"`, оборачивающего `StackPanel Orientation="Horizontal"`. Кнопки не сжимаются и не переносятся; то, что не помещается по ширине, уходит за край и достаётся свайпом/скроллом. Avalonia уже поддерживает touch-панорамирование `ScrollViewer` на Android/iOS без дополнительного кода.

Порядок кнопок слева направо — по смыслу, с визуальным разделителем (тонкая вертикальная граница, `Border Width=1` с приглушённым цветом, `Margin` по бокам) между группами:
`[Homing] [Сброс аварии] [Отключить]` │ `[Пуск] [Пауза] [Стоп]` │ `[Лог G-code]`

Обе зоны — фиксированной высоты вне зависимости от ширины экрана (зона 2 никогда не переносится на 2-ю строку, только скроллится по горизонтали), поэтому суммарная высота шапки перестаёт зависеть от ширины окна — `ComputeJoystickRadius` получает стабильный `headerHeight` при любой ширине, а не только когда `WrapPanel` случайно не переносит строки.

## Визуальная симметрия

- Единый `Padding`/высота для всех кнопок зоны действий через отдельный style-класс (см. ниже) — сейчас `Пуск`/`Стоп` (`primary`/`danger`) визуально тяжелее равных им по важности `Homing`/`Сброс аварии`, потому что применяются к разным базовым стилям без общего выравнивания.
- Единый `ItemSpacing` между кнопками внутри группы; больший отступ (или разделитель) — между группами.
- Зона 1 читается как единая строка статуса слева направо: связь → станок → программа — соответствует порядку, в котором пользователь обычно проверяет состояние.

## Touch-таргеты

Кнопки зоны действий получают отдельный style-класс `Button.header-action` с увеличенным `Padding`, дающим минимум 44px эффективной высоты нажатия (сейчас общий `ButtonPadding=16,10` в `Themes/HudControls.axaml` даёт около 40px с учётом текущего `FontSize`). Класс применяется только в шапке — остальные кнопки приложения (внутри панели программы, в диалогах) не затрагиваются.

## Изменения в `ConnectionView.axaml`

Компонент перестаёт содержать кнопки `Homing`/`Сброс аварии`/`Отключить` — они переезжают в `MainView.axaml`, в единую зону действий, с прямым биндингом на `Connection.HomeCommand` / `Connection.ResetAlarmCommand` / `Connection.DisconnectCommand` — по уже существующему в файле прецеденту (`Command="{Binding Connection.ToggleGCodeLogCommand}"` для кнопки «Лог G-code», которая тоже обращается к `ConnectionViewModel` в обход `ConnectionView`).

После этого `ConnectionView.axaml` содержит только зону статуса: индикатор + метка состояния соединения, машинное состояние/позиция, баннер ошибки. Он используется через `DataTypeViewLocator.RegisterGlobal<ConnectionViewModel, ConnectionView>()` (`App.axaml.cs:24`) и на данный момент единственное место использования — `ContentControl x:Name="ConnectionStatus"` в `MainView.axaml`; регистрация глобальная, так что смена состава компонента не ломает других потребителей (их сейчас нет), но сохраняет компонент переиспользуемым для статуса подключения где-либо ещё в будущем.

Модальное окно подключения (`MainView.axaml:310-331`, показывается до установления связи) `ConnectionView` не использует — отдельная инлайн-разметка, не затрагивается этим дизайном.

## `MainView.axaml.cs`: без изменений в формуле

`ComputeJoystickRadius` (сигнатура и логика) не меняется — по-прежнему принимает `headerHeight` через `HeaderBorder.Bounds.Height` с фолбэком `HeaderFallbackHeight` на первом кадре. Меняется только фактическое поведение: при новой 2-строчной без-переноса структуре шапки `HeaderBorder.SizeChanged` перестаёт срабатывать на изменения ширины (высота стабильна), срабатывает только при появлении/исчезновении баннера ошибки — что и является единственным легитимным случаем реального изменения высоты шапки.

## Затронутые файлы

- `ArctZ/Views/MainView.axaml` — зона 1 (статус) и зона 2 (`ScrollViewer` + `StackPanel Orientation="Horizontal"` с разделителями) вместо текущего `WrapPanel(PlaybackButtons)`; новые кнопки Homing/Сброс/Отключить с прямым биндингом на `Connection.*Command`.
- `ArctZ/Views/ConnectionView.axaml` — удаление трёх кнопок действий, компонент сохраняет только статус.
- `ArctZ/Themes/HudControls.axaml` — новый style-класс `Button.header-action` (увеличенный touch-таргет) и стиль разделителя групп.

## Тестирование

View-тестов в решении нет (см. прецедент в `2026-08-04-three-band-main-layout-design.md`). Проверка:
- `dotnet build ArctZ.Desktop/ArctZ.Desktop.csproj` — компиляция XAML/code-behind после переноса кнопок между файлами.
- Через skill `run` / `mobile-build-setup` — запуск `ArctZ.Android` (или `ArctZ.Browser` как приближение к touch-раскладке) на нескольких ширинах экрана, проверить: зона статуса не переносится, зона действий скроллится по горизонтали свайпом без переноса кнопок, разделители групп видны, высота шапки не меняется при изменении ширины окна (только при появлении баннера ошибки).
- Ручная проверка тач-таргетов — кнопки зоны действий не менее 44px по высоте на устройстве.

## Не в скоупе

- Изменение состава/логики самих команд (`HomeCommand`, `ResetAlarmCommand` и т.д.) — только перемещение кнопок между файлами.
- Модальное окно подключения (`MainView.axaml:310-331`) — не трогается.
- Средняя часть (панель программы) и нижняя часть (джойстики) `ContentGrid` — не трогаются, дизайн касается только шапки.
- Иконки вместо текстовых подписей на кнопках — не запрошено, кнопки остаются текстовыми.
