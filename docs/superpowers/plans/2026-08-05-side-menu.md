# Боковое меню + перенос кнопки лога G-code — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** добавить боковое меню (drawer), вызываемое гамбургером в шапке, и перенести в него кнопку «Лог G-code» из свайп-ряда действий.

**Architecture:** `ProgramViewModel` получает `IsSideMenuOpen` + три команды (`ToggleSideMenuCommand`/`CloseSideMenuCommand`/`OpenGCodeLogCommand`) по прецеденту уже существующей пары `IsLibraryOpen`/`OpenLibraryCommand`/`CloseLibraryCommand`. `MainView.axaml` получает гамбургер-кнопку в `HeaderStatusRow` и новый оверлей бокового меню в `RootPanel`, построенный тем же паттерном (`Border` scrim + центрированная/прижатая карточка), что и оверлей «Библиотека».

**Tech Stack:** Avalonia UI, CommunityToolkit.Mvvm (`[ObservableProperty]`/`[RelayCommand]`), xUnit.

## Global Constraints

- Закрытие меню — только по явным действиям (✕ или выбор пункта), без клика по скриму — так устроены все существующие модалки в `MainView.axaml`.
- Без анимации выезда (slide) — в проекте есть только fade-in при первом появлении (`Border.reveal-*`), новый паттерн не вводим.
- Панель самого лога G-code (`MainView.axaml:294-315`, top-right, `Connection.IsGCodeLogOpen`) не меняется — меняется только точка вызова.
- Переиспользовать существующие style-классы (`Button.icon-action`, `Button.header-action`, `TextBlock.section-heading`) — новых классов не создавать.

Полная спека: `docs/superpowers/specs/2026-08-05-side-menu-design.md`.
