# Research Deep — глубокое исследование

## Триггер
`/research-deep`

## Рабочий процесс

### Шаг 1: Автоматический поиск плана
Найти файл `*/outline.yaml` в текущем рабочем каталоге, прочитать список элементов, конфигурацию выполнения (включая items_per_agent).

### Шаг 2: Проверка возобновления
- Проверить уже готовые JSON-файлы в output_dir
- Пропустить уже выполненные элементы

### Шаг 3: Пакетное выполнение
- Разбить на пакеты по batch_size (перед следующим пакетом требуется подтверждение пользователя)
- Каждый агент обрабатывает items_per_agent элементов
- Запустить web-search-agent (фоново, параллельно, вывод задач отключён)

**Получение параметров**:
- `{topic}`: поле topic из outline.yaml
- `{item_name}`: поле name элемента
- `{item_related_info}`: полное yaml-содержимое элемента (name + category + description и т.д.)
- `{output_dir}`: execution.output_dir из outline.yaml (по умолчанию: ./results)
- `{fields_path}`: абсолютный путь к {topic}/fields.yaml
- `{output_path}`: абсолютный путь к {output_dir}/{item_name_slug}.json (slugify item_name: пробелы заменить на _, спецсимволы удалить)

**Жёсткое ограничение**: следующий промпт должен быть воспроизведён строго как есть, заменяя только переменные в {xxx}; не изменяйте структуру и формулировки.

**Шаблон промпта**:
```python
prompt = f"""## Задача
Исследовать {item_related_info}, вывести структурированный JSON в {output_path}

## Определения полей
Прочитать {fields_path}, чтобы получить все определения полей

## Требования к выводу
1. Выводить JSON согласно полям, определённым в fields.yaml
2. Помечать неопределённые значения полей меткой [uncertain]
3. Добавить в конце JSON массив uncertain, перечислив все неопределённые поля
4. Все значения полей должны быть на английском языке

## Путь вывода
{output_path}

## Валидация
После завершения вывода JSON запустить скрипт валидации, чтобы убедиться в полном покрытии полей:
python ~/.claude/skills/research/validate_json.py -f {fields_path} -j {output_path}
Задача считается завершённой только после прохождения валидации.
"""
```

**Пример на одном шоте** (предположим, исследуется GitHub Copilot):
```
## Задача
Research name: GitHub Copilot
category: International Product
description: разработан Microsoft/GitHub, первый массовый AI-ассистент по написанию кода, ~40% доли рынка, вывести структурированный JSON в {project_dir}/results/GitHub_Copilot.json

## Определения полей
Прочитать {project_dir}/fields.yaml, чтобы получить все определения полей

## Требования к выводу
1. Выводить JSON согласно полям, определённым в fields.yaml
2. Помечать неопределённые значения полей меткой [uncertain]
3. Добавить в конце JSON массив uncertain, перечислив все неопределённые поля
4. Все значения полей должны быть на английском языке

## Путь вывода
{project_dir}/results/GitHub_Copilot.json

После завершения вывода JSON запустить скрипт валидации, чтобы убедиться в полном покрытии полей:

Задача считается завершённой только после прохождения валидации.
```

### Шаг 4: Ожидание и мониторинг
- Дождаться завершения текущего пакета
- Запустить следующий пакет
- Отображать прогресс

### Шаг 5: Итоговый отчёт
После завершения всех элементов вывести:
- Количество завершённых
- Элементы с ошибками/пометкой uncertain
- Каталог вывода

## Конфигурация агента
- Фоновое выполнение: да
- Вывод задач (Task Output): отключён (у агента есть явный выходной файл по завершении)
- Поддержка возобновления: да
