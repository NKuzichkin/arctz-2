# Research Report - Сводный отчёт

## Триггер
`/research-report`

## Рабочий процесс

### Шаг 1: Найти каталог с результатами
Найти `*/outline.yaml` в текущем рабочем каталоге, прочитать конфигурацию `topic` и `output_dir`.

### Шаг 2: Просканировать необязательные поля для сводки
Прочитать все JSON-результаты, извлечь поля, подходящие для отображения в оглавлении (числовые, короткие метрики), например:
- github_stars
- google_scholar_cites
- swe_bench_score
- user_scale
- valuation
- release_date

Использовать AskUserQuestion, чтобы спросить пользователя:
- Какие поля отображать в оглавлении помимо названия элемента?
- Предоставить динамический список вариантов (на основе фактических полей в JSON)

### Шаг 3: Сгенерировать Python-скрипт конвертации
Сгенерировать `generate_report.py` в каталоге `{topic}/`, требования к скрипту:
- Прочитать все JSON из output_dir
- Прочитать fields.yaml, чтобы получить структуру полей
- Охватить все значения полей из каждого JSON
- Пропускать поля, значения которых содержат `[uncertain]`
- Пропускать поля, перечисленные в массиве `uncertain`
- Сгенерировать markdown-отчёт в формате: оглавление (с якорными ссылками + выбранными пользователем сводными полями) + подробное содержание (по категориям полей)
- Сохранить в `{topic}/report.md`

**Требования к формату оглавления**:
- Должно включать каждый элемент
- Каждый элемент отображает: номер, название (якорная ссылка), выбранные пользователем сводные поля
- Пример: `1. [GitHub Copilot](#github-copilot) - Stars: 10k | Score: 85%`

#### Технические требования к скрипту (обязательны к соблюдению)

**1. Совместимость со структурой JSON**
Поддерживать две структуры JSON:
- Плоская структура: поля напрямую на верхнем уровне `{"name": "xxx", "release_date": "xxx"}`
- Вложенная структура: поля во вложенном словаре категории `{"basic_info": {"name": "xxx"}, "technical_features": {...}}`

Порядок поиска поля: верхний уровень -> ключ соответствия категории -> обход всех вложенных словарей

**2. Многоязычное сопоставление категорий**
Названия категорий из fields.yaml и ключи JSON могут быть в любой комбинации (RU-RU, RU-EN, EN-RU, EN-EN). Необходимо установить двустороннее сопоставление:
```python
CATEGORY_MAPPING = {
    "Basic Info": ["basic_info", "Basic Info"],
    "Technical Features": ["technical_features", "technical_characteristics", "Technical Features"],
    "Performance Metrics": ["performance_metrics", "performance", "Performance Metrics"],
    "Milestone Significance": ["milestone_significance", "milestones", "Milestone Significance"],
    "Business Info": ["business_info", "commercial_info", "Business Info"],
    "Competition Ecosystem": ["competition_ecosystem", "competition", "Competition Ecosystem"],
    "History": ["history", "History"],
    "Market Positioning": ["market_positioning", "market", "Market Positioning"],
}
```

**3. Форматирование сложных значений**
- Список словарей (например, key_events, funding_history): форматировать каждый словарь как одну строку, разделять ключ-значение через ` | `
- Обычный список: короткие списки объединять через запятую, длинные списки отображать с переносами строк
- Вложенный словарь: рекурсивное форматирование, отображать через точку с запятой или переносы строк
- Длинные текстовые строки (более 100 символов): добавлять переносы `<br>` или использовать формат цитаты для читаемости

**4. Сбор дополнительных полей**
Собирать поля, которые существуют в JSON, но не определены в fields.yaml, помещать в категорию "Прочая информация". Обратить внимание на фильтрацию:
- Внутренние поля: `_source_file`, `uncertain`
- Ключи верхнего уровня вложенной структуры: `basic_info`, `technical_features` и т.п.
- Массив `uncertain`: отображать каждое название поля на отдельной строке, не сжимать в одну строку

**5. Пропуск неопределённых значений**
Условия пропуска:
- Значение поля содержит строку `[uncertain]`
- Название поля присутствует в массиве `uncertain`
- Значение поля — None или пустая строка

### Шаг 4: Выполнить скрипт
Запустить `python {topic}/generate_report.py`

## Результат
- `{topic}/generate_report.py` - скрипт конвертации
- `{topic}/report.md` - сводный отчёт
