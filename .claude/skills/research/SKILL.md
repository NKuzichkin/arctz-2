# Навык Research — предварительное исследование

## Триггер
`/research <тема>`

## Рабочий процесс

### Шаг 1: Сгенерировать первичный каркас на основе знаний модели
На основе темы используйте существующие знания модели, чтобы сгенерировать:
- Список основных объектов/элементов исследования в этой области
- Предлагаемый каркас полей (field framework) исследования

Выведите {step1_output}, используйте AskUserQuestion для подтверждения:
- Нужно ли добавить/удалить элементы?
- Соответствует ли каркас полей требованиям?

### Шаг 2: Дополнение веб-поиском
Используйте AskUserQuestion, чтобы уточнить временной диапазон (например, последние 6 месяцев, с 2024 года, без ограничений).

**Получение параметров**:
- `{topic}`: тема исследования, введённая пользователем
- `{YYYY-MM-DD}`: текущая дата
- `{step1_output}`: полный вывод шага 1
- `{time_range}`: временной диапазон, указанный пользователем

**Жёсткое ограничение**: следующий промпт должен быть воспроизведён строго как есть, заменяя только переменные в {xxx}; не изменяйте структуру и формулировки.

Запустите 1 агента web-search-agent (в фоне), **шаблон промпта**:
```python
prompt = f"""## Задача
Тема исследования: {topic}
Текущая дата: {YYYY-MM-DD}

На основе следующего первичного каркаса дополните его новейшими элементами и рекомендуемыми полями исследования.

## Существующий каркас
{step1_output}

## Цели
1. Проверить, не упущены ли в существующих элементах важные объекты
2. Дополнить элементы на основе упущенных объектов
3. Продолжить поиск элементов, связанных с {topic}, в пределах {time_range}, и дополнить
4. Дополнить новые поля

## Требования к выводу
Верните структурированный результат напрямую (не записывайте файлы):

### Дополнительные элементы
- item_name: краткое пояснение (почему его нужно добавить)
...

### Рекомендуемые дополнительные поля
- field_name: описание поля (зачем нужно это измерение)
...

### Источники
- [Источник1](url1)
- [Источник2](url2)
"""
```

**Пример на одном шоте** (предположим, исследуется история AI Coding):
```
## Задача
Тема исследования: AI Coding History
Текущая дата: 2025-12-30

На основе следующего первичного каркаса дополните его новейшими элементами и рекомендуемыми полями исследования.

## Существующий каркас
### Список элементов
1. GitHub Copilot: разработан Microsoft/GitHub, первый массовый AI-ассистент по написанию кода
2. Cursor: AI-first IDE на основе VSCode
...

### Каркас полей
- Basic Info: name, release_date, company
- Technical Features: underlying_model, context_window
...

## Цели
1. Проверить, не упущены ли в существующих элементах важные объекты
2. Дополнить элементы на основе упущенных объектов
3. Продолжить поиск элементов, связанных с AI Coding History, в пределах since 2024, и дополнить
4. Дополнить новые поля

## Требования к выводу
Верните структурированный результат напрямую (не записывайте файлы):

### Дополнительные элементы
- item_name: краткое пояснение (почему его нужно добавить)
...

### Рекомендуемые дополнительные поля
- field_name: описание поля (зачем нужно это измерение)
...

### Источники
- [Источник1](url1)
- [Источник2](url2)
```

### Шаг 3: Спросить пользователя о существующих полях
Используйте AskUserQuestion, чтобы узнать, есть ли у пользователя файл с уже определёнными полями; если да — прочитать и объединить.

### Шаг 4: Сгенерировать план (отдельными файлами)
Объедините {step1_output}, {step2_output} и существующие поля пользователя, сгенерируйте два файла:

**outline.yaml** (элементы + конфигурация):
- topic: тема исследования
- items: список объектов исследования
- execution:
  - batch_size: количество параллельных агентов (подтвердить через AskUserQuestion)
  - items_per_agent: количество элементов на агента (подтвердить через AskUserQuestion)
  - output_dir: каталог для результатов (по умолчанию: ./results)

**fields.yaml** (определения полей):
- Категории полей и их определения
- Для каждого поля: name, description, detail_level
- Иерархия detail_level: brief -> moderate -> detailed
- uncertain: список неопределённых полей (зарезервированное поле, заполняется автоматически на этапе глубокого исследования)

### Шаг 5: Вывод и подтверждение
- Создать каталог: `./{topic_slug}/`
- Сохранить: `outline.yaml` и `fields.yaml`
- Показать пользователю для подтверждения

## Путь вывода
```
{current_working_directory}/{topic_slug}/
  ├── outline.yaml    # список элементов + конфигурация выполнения
  └── fields.yaml     # определения полей
```

## Последующие команды
- `/research-add-items` — дополнить элементы
- `/research-add-fields` — дополнить поля
- `/research-deep` — начать глубокое исследование
